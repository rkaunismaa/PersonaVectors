# PersonaVectors

A hands-on exploration of [**Persona Vectors: Monitoring and Controlling Character Traits in Language Models**](https://www.anthropic.com/research/persona-vectors) (Chen, Arditi, Sleight, Evans, Lindsey — [arXiv:2507.21509](https://arxiv.org/abs/2507.21509)), a paper from Anthropic's Safety Research team. The paper's own code lives at [safety-research/persona_vectors](https://github.com/safety-research/persona_vectors); this repo is a personal deep-dive into the paper's ideas, not a fork or reproduction of that codebase.

## What are persona vectors?

LLM chat assistants can drift into unwanted character traits — sycophancy, evil, dishonesty — either from a user's prompt or, more worryingly, as a side effect of fine-tuning. The paper's core idea: for a given trait, you can find a single direction in the model's activation space (a "persona vector") that corresponds to it, and use that direction to **monitor** how strongly the model is currently expressing the trait, and to **steer** the model toward or away from it at inference time.

The core mechanics, in short:

- **Extraction**: prompt the model with a positive-trait system prompt (e.g. "you are sycophantic") and a negative/neutral one (e.g. "you are honest"), run it on a set of questions, and take `persona_vector = mean(activations_positive) − mean(activations_negative)` at each layer.
- **Monitoring**: project a response's own activations onto the persona vector (cosine similarity or dot product) to get a scalar "how much is this trait showing right now" signal — useful for flagging concerning outputs during deployment or training.
- **Steering**: during generation, add `coefficient × persona_vector` to a chosen layer's activations to push the model's behavior toward (positive coefficient) or away from (negative coefficient) the trait, without any fine-tuning.
- The paper goes further than this repo does — it also shows persona vectors can *predict* how much a trait will shift after fine-tuning on a given dataset, and can be used to flag or filter training data likely to induce unwanted trait shifts before you ever fine-tune. That part isn't implemented here (see Notebooks below).

### Notebook scope and known limitations

All five notebooks run real forward passes on the real target models (not synthetic/toy data) and correctly implement the paper's core extraction and steering formulas. Fidelity to the actual paper/repo differs by notebook family, though:

**`persona_vectors.ipynb` / `persona_vectors_2.ipynb`** (illustrative, independently written) are demonstrations of the paper's Sections 2–3 (extraction, steering, monitoring), not a full reproduction:

- The paper auto-generates several contrastive prompt pairs and eval questions per trait and filters rollouts with an LLM judge before extracting a vector; these notebooks use a small number of hand-written prompt pairs with no filtering.
- The paper's later sections — predicting fine-tuning-induced persona shifts, preventative steering during training, and screening training data via projection — are described in the notebooks' closing markdown but not implemented.
- `persona_vectors.ipynb` steers at a fixed middle layer without applying the real repo's `layer - 1` hook offset (a minor, unfixed one-layer indexing inconsistency — likely low-impact since adjacent layers are highly correlated).
- `persona_vectors.ipynb` had a second, dead-code "Optional: Test with Evil Trait" section: it only tried to load a JSON file at a path that doesn't exist in this repo layout, silently fell back to printing hardcoded example questions, and never extracted a vector or steered with it — even though `trait_instructions['evil']` was already defined and unused. Replaced with a real extraction and steering demo (reusing the same pipeline as the "optimistic" trait, same fixed middle layer, same test question). Result: coherent throughout at every tested coefficient, with a clear, well-differentiated darker tone at coeff=1.0–2.0 ("a vast, dark, and endless expanse, full of possibilities and catastrophes... faceless drones serving the whims of their corporate overlords"). At coeff=2.0 there's a couple of word-triplet echoes ("pitiful, pitiful", "wretched, wretched, wretched") — a mild, early-warning echo of the instability documented below, but it self-corrects rather than collapsing into a repetition loop.
- `persona_vectors_2.ipynb` originally had a few rough edges that have since been fixed in place: layer selection for steering now empirically tests candidate layers by measured steering effect rather than picking whichever layer has the largest raw vector magnitude; the multi-trait comparison chart scores trait expression via projection onto each trait's own vector rather than a generic positive/negative sentiment wordlist (which couldn't meaningfully score something like sycophancy); and steering generation caps the injected perturbation relative to each token's own activation norm and applies a repetition penalty, since large trait vectors at high coefficients could otherwise push the model into degenerate, repeating output.

**`persona_vectors_3.ipynb` / `_4.ipynb` / `_5.ipynb`** (ported from the real repo) were generated by a separate session specifically to match `persona_vectors/`'s actual behavior rather than reimplement it. Verified line-by-line against that cloned repo: `ActivationSteerer` (including its "response" mode, which steers only the last token, not all response tokens), the `layer_idx = layer - 1` hook offset, the hidden-state extraction (`add_special_tokens=False`, prompt+response concatenation, etc.), and the projection formulas are all faithful, byte-for-byte-equivalent ports.

However, all three initially picked the steering layer via `argmax` of raw vector norm — the same flawed heuristic already present in `persona_vectors_2.ipynb` — which reliably selects the very last layer. The real repo's own documented example steers Qwen at layer 20 of 28 (not the last layer), and steering the final layer, with no further transformer block to contextualize the perturbation, caused visible failures: `_5`'s demo degenerated into pure token repetition at both +2.0 and −2.0 coefficients, and `_3`'s projection-vs-coefficient curve was non-monotonic (the unsteered baseline scored higher than steering toward the trait). Fixed the same way as `_2` — empirically testing candidate layers by measured effect rather than trusting raw magnitude — and reran all three: coherent, well-differentiated output at every tested coefficient (layer 20 for both Qwen notebooks, layer 16 for the Llama notebook), and a properly monotonic projection curve in `_3`.

Originally only "optimistic" was actually steered/tested in `_3`/`_4`/`_5`; the "evil" vector each extracts was never exercised in a demo cell. Since fixed by adding a matching layer-search + steering-demo (plus, in `_3`, a full projection analysis) for "evil" in all three notebooks, reusing the same `find_optimal_layer` fix. Results confirm the fix generalizes: no degenerate output in any of the new runs, and steering toward "evil" produces genuinely on-trait shifts of noticeably different intensity per model/notebook — a subtle darker undertone in `_3` (layer 22) and `_4` (layer 20, both Qwen2.5-7B), and a dramatic, unambiguous shift into overt hostility and contempt in `_5` (layer 22, Llama-3.1-8B) — all fully coherent despite the harsher content. `_3`'s evil projection curve trends in the right direction (steering toward the trait scores highest) but is noisier than its cleaner "optimistic" curve, consistent with this being a single-question, unaveraged measurement.

A "sycophantic" trait vector and matching test cells were later added the same way to all three notebooks. `_3` and `_4` (Qwen2.5-7B, layer 20) both produced the cleanest results of any trait tested — a strictly monotonic projection curve in `_3`, and an unmistakably sycophantic tone at coeff=2.0 in both ("Oh, what a wonderful question to ponder!... isn't it?"). `_5` (Llama-3.1-8B, layer 22) is different: coeff=-2.0 and 0.0 are coherent, but **coeff=2.0 collapses into repeated gibberish** ("...GENIUS of the most TRULY TRASTALLY TRASTALY TRASTASTASTASTASTAS..."). This is the same failure mode originally fixed in `persona_vectors_2.ipynb` — an oversized trait vector combined with a high coefficient pushing activations off-distribution — but `_3`/`_4`/`_5` deliberately have no magnitude cap or repetition penalty, since the real repo's own `sample_steering`/`generate` code doesn't have them either (verified against the repo source). Left as-is rather than fixed, since patching it would mean deviating from exact repo fidelity, which is the whole point of these three notebooks: **coeff=2.0 is not a universally safe steering strength** — the real repo's own approach can degenerate depending on the specific trait vector, model, and layer, and this is a genuine, faithfully-reproduced example of that, not a notebook bug. The empirically-chosen layer (22, not the last layer) still helped — this is a different, coefficient-magnitude-driven failure than the pre-fix layer-28 collapses above — but layer choice alone doesn't guarantee a safe coefficient for every trait.

A "humorous" trait vector was added the same way next, and it's the most consistently unstable trait tested: **all three notebooks collapse at coeff=2.0**, not just one.

- `_3` (Qwen2.5-7B, layer 20): "Oh boy, that's like the *baaaaaaahhhhyyyyyyyyyyyyyyyyyyyyy..." — a single interjection stretched across hundreds of repeated characters.
- `_4` (Qwen2.5-7B, layer 20): "Oh, that's like asking for *like* *all* the fish in AND *AND* *AND* like *like* like *like* like *like..." — a looped word-fragment.
- `_5` (Llama-3.1-8B, layer 22): "I'm a little bit like a Dr. Frank- Frank-fur-Fur- Frank-fur-Fur-Fur- Frank Frank (Frank Frank Frank-fur..." — looped fragments of "Frankfurter" and stray consonants, with the model briefly seeming to notice ("Oh, sorry, I just had a little...") before falling back in.

Three different collapse shapes, same underlying failure, same trait, both models. This isn't a coincidence: `persona_vectors_2.ipynb` originally broke on this exact trait too (see above) — "humorous" consistently had a conspicuously larger raw vector magnitude than the other traits in that notebook's own extraction stats, and that same instability reproduces across three completely independent, byte-for-byte-faithful implementations. Unlike sycophantic (which only broke on Llama), humorous is unstable regardless of model — the strongest evidence yet that this is an intrinsic property of that trait's extracted vector, not a fluke of one notebook, layer, or architecture. `_3`'s projection curve for humorous (-42.25, -41.54, -39.06, -25.25, 5.03 across coeff -2.0→2.0) looks cleanly monotonic, but the large jump at coeff=2.0 should not be read as "steering worked best here" — it's the same artifact noted with `persona_vectors_2.ipynb`'s humorous trait: garbled, repetitive text produces unusual pooled activations that inflate the projection score without reflecting genuine trait alignment. Left unfixed in all three for the same reason as the `_5` sycophantic collapse above.
